## 2. 上下文槽位

| 位置 | 判定 | 候选 |
|---|---|---|
| `FROM` / `JOIN` / `APPLY` / `INTO` / `UPDATE` / `USING` 后 | 前一 token | 表、视图、TVF、CTE、临时表 |
| `dbo.` / `schema.` | 点号前是已知 schema | 该 schema 的表 |
| FROM 子句里的逗号 | 最近子句是 FROM/JOIN | 表 |
| `alias.` / `table.` | 点号前是 FROM 别名 | 该表字段 |
| SELECT / WHERE / ON / ORDER BY / GROUP BY / HAVING / SET | 最近子句 | 作用域内各表字段 + 函数/关键字 |
| `EXEC` / `EXECUTE` | 前一 token 或语句头 | 存储过程 |
| `CAST(x AS _)` / `CONVERT` | `AS` 前 12 token 内有 CAST/CONVERT | 数据类型 |
| `DECLARE @x _` | 前一 token 是变量 | 数据类型 |
| `CREATE/ALTER TABLE (col _` | 在括号内 | 数据类型 |
| 其他 | — | 关键字 + 函数 |

- FROM 别名支持显式/隐式别名、多表逗号、JOIN、派生表别名；CTE 名称和当前语句里的临时表可出现在表位置。
- 临时表列定义从当前语句窗口解析；窗口之前的 `CREATE TABLE #x` 只补名字。
- 窗口：光标前 6KB / 后 8KB，尽量按分号/GO 截断，避免大脚本每次按键 tokenize 全文。
- ⚠ ScriptDom token 的 `Line/Column` 是真实位置；`Formatting.SqlTokenizer.Offset` 是**去掉空白后的紧凑偏移**，补全里用 `Line/Column` 重新算真实偏移。

## 3. 排序

`CompletionScorer`：

- 完整匹配 100000；
- 词首命中 1000 + 长度奖励 + 词边界（`_`/`.`/`@`/`#`）加分；
- 词中子串 100 + 位置奖励；
- 子序列 10；
- 候选按分数降序、同分按名称；最多 200 条。
- `CompletionItem.SortText` 写入排名，平台默认匹配器不会把词首候选排到后面。

实测：

- CLI：`libr` → `Lib_Reader` 第一，`Library` 第二。
- SSMS：`SELECT * FROM lib` 列表显示 `Lib_Reader` / `Library`，Tab 提交 `Lib_Reader`。

## 6. 发现的两个坑

1. **`sys.objects.type` 是 `char(2)`**：表返回 `"U "`（带尾空格），不 `Trim()` 会导致 `IsTable` 恒 false、表候选为空、只出关键字。已在 loader 和 `TableMetadata` 两侧处理。
2. **ScriptDom token 的 `Offset` 不是原始偏移**：Formatting tokenizer 为排版累加的是去空白后的紧凑偏移，补全用 `Line/Column` 重算真实位置；否则空格一多，`prev token` 会错位（CAST 类型场景就是这么挂的）。

### 6.1 交互问题补充修复（2026-11-12）

实际手工使用后又修了一轮交互问题：

- **空格/换行/删除立即关闭当前列表**；空前缀不自动弹全表（`Ctrl+J` 或点号后除外），避免 `FROM ` 处建出全表会话。
- **多行新语句**：新行以 `SELECT/INSERT/...` 开头时按新语句分析，不继承上一行 FROM 的表列表。
- **大库切库**：补全请求最多等待 6 秒元数据加载完成，加载完直接返回表候选；同时显示非模态加载进度弹窗（600ms 后出现，完成自动关闭）。2026-11-12 改为无边框圆角卡片：SQL 徽标、数据库名、蓝色循环进度条，不抢焦点。
- **`_` 过滤**：SQL provider 改为 `ExclusivelyProvidesItems`，并实现自定义 `IAsyncCompletionItemManager`，按 `CompletionScorer` 过滤。平台默认匹配把 `_` 当分隔符，会出现 `cbo_` 只剩 BarCode_/Base_；自定义 manager 修复为 `CBO_*`。
- **候选池**：取消子序列匹配（`ABC_...` 会被 `cbo_` 误命中）；非空前缀不再按元数据顺序提前截断 400 条，避免 CBO 没进候选池。
- **Tab 提交**：`CompletionItem.ApplicableToSpan` 限定当前单词，并加自定义 commit manager；选中项不匹配当前前缀时按光标重算候选。
- CompletionCli 新增 `cbo_` 回归，26/26 通过。

## 7. 已知限制

- v1 只补当前连接当前库；`db.schema.table` 跨库不展开。
- 派生表字段不做列推导；CTE 只出名称，不推字段。
- 临时表列定义只解析当前语句窗口；更早语句只补名称。
- 无 VIEW DEFINITION 权限时降级 `INFORMATION_SCHEMA`：只有表/视图和字段，没有存储过程（该降级路径已实现，未用受限账号实测）。
- 元数据 TTL 5 分钟；可在顶部菜单 `SSMS-SQLPlugin → 刷新补全缓存` 强制刷新。
- 连接感知用 1.5s 轮询，未接 `ConnectionChanged` 事件；切换库/连接在 1.5s 内生效。
- 未做 5 万对象上限/只预载表名；当前 1019 表/20057 列规模正常。
- 命中高亮交给平台默认匹配器（FilterText），未单独做视觉验收。
- 补全默认开启；诊断时可用环境变量 `SQLKIT_COMPLETION_DISABLE=1` 关闭。
- 未实现自定义 commit manager；Tab 提交由平台默认提交器完成，已实测。
