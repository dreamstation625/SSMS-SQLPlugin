## S4.3 安装器

源码：`src/SsmsSqlPlugin.Installer`

- `SSMS-SQLPlugin-Setup.exe` 单文件，内嵌刚打好的 VSIX（`Payload.zip`）。
- 调用 SSMS 自带的 `VSIXInstaller.exe` 注册/注销扩展。不能手工把文件复制到新目录：SSMS 只识别由 VSIXInstaller 注册过的扩展目录，卸载后复制到新目录不会加载。
- 安装器自动查找 `Program Files` / `Program Files (x86)` 下的 `Microsoft SQL Server Management Studio*`。
- 安装前若已有扩展，先调用 VSIXInstaller 卸载再安装，避免同版本更新被拒绝。
- 复制 4 个 DLL、pkgdef、vsixmanifest 的工作交给 VSIXInstaller；安装器只负责定位、调用和状态显示。
- 安装后写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\SSMS-SQLPlugin`，卸载命令指向 `%LOCALAPPDATA%\SsmsSqlPlugin\Installer\SSMS-SQLPlugin-Setup.exe /uninstall`。
- 安装/卸载期间显示遮罩 + 跑马灯进度条，禁用按钮并阻止关闭窗口；避免 VSIXInstaller 调用期间看起来假死。
- 安装/卸载前检测 SSMS 是否运行；运行中直接提示关闭，不杀进程。
- 安全软件（如 360）可能拦截 VSIXInstaller 修改 `SSMS.exe.config`；安装器超时提示里会要求先处理安全软件弹窗。
- 卸载只让 VSIXInstaller 注销扩展，保留 `%LOCALAPPDATA%\SsmsSqlPlugin` 下的 `options.json`、`autosave.cfg`、`data.db`。
- 支持命令行：`/install /silent`、`/uninstall /silent`（便于自动测试）。

构建：

```bash
python src/SsmsSqlPlugin.Vsix/build.py --no-deploy --installer
```

产物：

- `src/SsmsSqlPlugin.Vsix/dist/SSMS-SQLPlugin.vsix`
- `src/SsmsSqlPlugin.Vsix/dist/SSMS-SQLPlugin-Setup.exe`

### 实机验证（2026-11-12）

```
/install /silent   → 退出码 0；VSIXInstaller 注册扩展目录
启动 SSMS          → 顶部菜单 SSMS-SQLPlugin 出现
/uninstall /silent → 退出码 0；扩展目录移除；data.db/options.json 保留；注册表项删除
再次 /install      → 退出码 0；生成新的已注册扩展目录
再次启动 SSMS      → 菜单正常出现
```

手工复制到新建目录不会被 SSMS 识别，这是首版安装器“卸载后重装不生效”的根因；现已改为 VSIXInstaller 注册。

安装器界面：`docs/images/installer.png`。

## S4.4 CI 与 Release

`.github/workflows/build.yml`：

- windows-latest
- .NET 10 + Python 3.12
- `build.py --no-deploy --installer`
- FormatCli 内置用例 + Corpus
- 上传 VSIX / Setup.exe artifact

`.github/workflows/release.yml`：

- 推 `v*` tag 触发
- 构建并跑回归
- 打包 `README.md` + VSIX + Setup.exe 为 `SSMS-SQLPlugin-<tag>.zip`
- 通过 `softprops/action-gh-release` 创建 Release

首次 Actions 运行失败在 `verify_pkgdef()`：GitHub Windows runner 的 Python 控制台是 cp1252，`build.py` 打印中文抛 `UnicodeEncodeError`。已在工作流设置 `PYTHONUTF8=1`，并给 stdout/stderr 加 `errors="replace"` 兜底。

第二次运行又暴露一个 CRLF 问题：`GO` 行正则不匹配 `\r`，整个文件被当成一个批次，Corpus 幂等失败。已在 `GoLine` 正则末尾加 `\r?`，并用 CRLF 语料本地回归通过。

## S4.7 v0.1.1 历史列表修复

SQL 历史窗口使用 `VirtualMode`，为补齐表头新增占位列后共有 10 列，但 `OnRetrieveVirtualItem` 仍只返回 9 个子项，打开列表时抛出 `InvalidOperationException`。

- 修复：按 `ListView.Columns.Count` 创建子项数组，前 9 项填数据，末尾占位列留空；无数据时的占位行同样按列数创建。
- 版本：程序集、VSIX 清单和安装器回退版本统一升到 `0.1.1`。
- 验证：本地重新部署后打开历史窗口（1 条记录），行正常渲染，无异常弹窗；截图 `tmp/history-fixed2.png`。
