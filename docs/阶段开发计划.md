# SSMS-SQLPlugin 阶段开发计划

> 版本 v1.0 ｜ 2026-11-10
> 配套台账：`docs/开发进度.md`（每段完成情况记在那里，本文件只写"要做什么、怎么算完"）

---

## 0. 执行原则

1. **每个阶段必须有可证伪的出口判据。** 「能跑起来」「看着正常」不算完成，必须有一条能执行的检查命令或能复现的现象。
2. **未过验收不进入下一阶段。** 确需带风险放行，必须在进度台账写明「放行理由 + 遗留风险」，不许静默跳过。
3. **探针代码用完即弃。** P0 阶段的探针工程在验证完不并入主干，结论写进文档、代码丢弃，避免把试验代码当架构。
4. **失败也要记。** 阻塞、放弃、判据不成立，都按完成一样登记，写清原因。
5. **每一步先读 `docs/开发进度.md`**，确认上一个阶段的真实状态，不凭记忆续做。

## 2. P0：骨架与可行性验证

> 目的不是做功能，是把「方案里猜的部分」变成「实测结论」。
> 产出：一个一次性探针工程 + 一份结论。
> 除 S0.7 外，所有代码在 S0.7 结束后删除。

### S0.1 构建链定案

| 项 | 内容 |
|---|---|
| 输入 | 环境已就绪（SSMS 22.11.12328.437 / VS 18.11.3 / VSSDK 已装） |
| 动作 | ① 确认 `dotnet build` 与 VS 自带构建器哪个能产出 VSIX；② 确认 NuGet 能否拉到 VSSDK 包；③ 确认 ScriptDom 引用方式（宿主目录 vs NuGet） |
| 产出 | `docs/构建说明.md`：一条能复现的构建命令 + 依赖清单 |
| 验收 | 在干净目录下按文档执行一次，能得到 `.vsix` 文件（大小 > 5KB） |
| 失败出口 | 若 VSIX 打包只能靠 IDE 手动操作 → 记录，改为「脚本 + 手工打包」双轨，不阻塞后续 |

### S0.2 最小 VSIX 加载（M0-1）

| 项 | 内容 |
|---|---|
| 动作 | 建包工程：一个 `AsyncPackage` + 一个命令「SSMS-SQLPlugin: Ping」+ pkgdef + `extension.vsixmanifest`（`InstallationTarget Id=Microsoft.VisualStudio.Ssms`，版本 `[22.0,23.0)`） |
| 产出 | `.vsix` + 部署脚本 |
| 验收 | ① VSIX 装进 SSMS 22.11 无报错；② 启动后 Tools 菜单出现该命令；③ 点击后 `%TEMP%\SsmsSqlPlugin\probe.log` 追加带时间戳的 `package loaded`；④ ActivityLog 无 error |
| 失败出口 | 按「pkgdef 未生效 → MEF 缓存 → 签名/杀软」顺序排查；记录每一步结果 |

### S0.3 补全管线条目（M0-2）

| 项 | 内容 |
|---|---|
| 动作 | MEF 导出 `IAsyncCompletionSource` + `IAsyncCompletionItemManager`，内容类型 `SQL`，返回固定候选 `SEL_PROBE` |
| 验收 | 在查询窗口输入 `sel`，列表出现 `SEL_PROBE`；`probe.log` 记录 `GetOrCreate` / `InitializeCompletion` 的调用次数与内容类型名 |
| 失败出口 | 内容类型名可能不是 `SQL`（打印实际值再适配）；若完全不触发 → 记 Plan B（快捷键唤起自绘弹窗），并把结论回写到方案 §5 |

### S0.4 连接契约（M0-3）

| 项 | 内容 |
|---|---|
| 动作 | 从 `SqlWorkbench.Interfaces.dll` 取 `ISqlEditorService`，调 `GetActiveEditorMoniker` + `GetConnectionForSpecificQueryEditor` |
| 验收 | ① 日志打印服务器名与库名；② 工具栏切库 / 执行 `USE` 后 2 秒内日志出现新库名；③ 记录单次调用耗时（用于验证「2~7ms，忙时 1908ms」这一说法） |
| 失败出口 | 契约拿不到实例 → 试 `Package.GetGlobalService` 与 MEF 导入两条路；都不行则退化为「用户手动绑定连接」 |

### S0.5 执行捕获（M0-4）

| 项 | 内容 |
|---|---|
| 动作 | 两条路各写一个探针：① `IVsTextViewFilter` 拦执行键；② `DTE.Commands.BeforeExecute`。分别记录能否拿到「执行的是选区还是全文」 |
| 验收 | 按 F5 与点工具栏按钮两种方式各执行一次，日志都能出现 SQL 原文前 100 字 + 耗时 + 行数 |
| 失败出口 | 拿不到行数/耗时 → 历史功能降级为「只记文本与时间」；拿不到原文 → 该路线废弃，换另一条 |

### S0.6 存储隔离（M0-5）

| 项 | 内容 |
|---|---|
| 动作 | 在 SSMS 进程内起独立 `AppDomain` 加载 SQLite，写 1000 条含 10KB 文本的记录 |
| 验收 | 写入无异常、SSMS 正常退出无崩溃、数据库文件大小符合预期；对比「不隔离」是否真的冲突（把冲突现象记下来） |
| 失败出口 | 隔离失败 → 改 append-only 日志文件 + 内存索引，重估 §6.2 |

### S0.7 结论汇总与方案修订

| 项 | 内容 |
|---|---|
| 动作 | 把 S0.1~S0.6 的结论写成 `docs/P0验证报告.md`；对 `开发方案.md` 做定向修订（只改被证伪的部分，不整体重写） |
| 验收 | 报告里每条结论都指向具体证据（日志片段/命令输出）；方案修订处有版本号与变更说明 |
| 附加 | 删除探针工程，或移入 `docs/spike/` 归档（不参与构建） |

## 3. P1：排版引擎（可并行，无宿主依赖）

| 编号 | 内容 | 验收判据 |
|---|---|---|
| S1.1 | 解析封装：`TSql180Parser` 包装、按 `GO` 切 batch、局部失败降级 | 100 条含语法错误的脚本，全部能返回「哪些 batch 成功、哪些原样保留」 |
| S1.2 | Document IR + Wadler printer | 宽度 100 的折行决策在 50 组构造上符合预期；IR 可单测（无 IO、无 UI） |
| S1.3 | SELECT 家族（CTE / 子查询 / 窗口函数 / PIVOT） | 语料库对应分组全部通过快照测试 |
| S1.4 | DML（INSERT / UPDATE / DELETE / MERGE） | 同上 |
| S1.5 | DDL（TABLE / PROC / VIEW / FUNCTION / INDEX） | 同上 |
| S1.6 | 流程控制（IF / WHILE / BEGIN-END / TRY-CATCH / CASE） | 缩进层级正确，嵌套 5 层不塌 |
| S1.7 | 风格配置（`.sqlkit.json` + 默认预设 + 查找顺序） | 改任一开关，输出随之变化；非法配置有明确报错 |
| S1.8 | 语料库与快照测试 | ≥500 条真实脚本；注释零丢失；二次格式化结果幂等（format(format(x)) == format(x)） |

**幂等性是硬指标**：不幂等说明规则有冲突，必须修到幂等才能进 P4。

## 5. P3：历史与文件快照

| 编号 | 内容 | 验收判据 |
|---|---|---|
| S3.1 | 存储层落地（SQLite + 隔离 + 单写线程 + WAL） | 1000 次写入无 `SQLITE_BUSY`；进程被杀后数据可恢复 |
