## 1. 关键决策：token 驱动，不用 AST 生成

**原方案 §4.2 写的是「AST → Document IR → printer」。实际实现改成了「token 流 → Document IR → printer」。**

原因是实测出来的：

```
GetTokenStream() 返回完整 token 流，包含：
  ✅ SingleLineComment / MultilineComment（带 Line/Column）
  ✅ WhiteSpace（含 \r\n）
  ✅ 每个 token 的精确位置
```

也就是说**注释就在 token 流里，位置信息完整**。而 ScriptDom 的 `SqlScriptGenerator` 会丢注释——这正是旧实现（S1.1）遇到注释只能整批跳过的根本原因。

**新架构**：

```
SQL 文本
  ├─ ① 按 GO 切批（GO 不是 T-SQL token，必须自己切）
  ├─ ② GetTokenStream → SqlToken 列表（注释、运算符都保留）
  │      └─ 语法错误不影响排版：token 流对残缺 SQL 也有效
  ├─ ③ AST 只用来找语句边界（token 索引区间），文本仍从 token 出
  ├─ ④ token → Document IR
  └─ ⑤ Wadler printer 按行宽渲染
```

AST 只承担"语句在哪开始/结束"这一件事，不参与文本生成。这样既准确定位语句，又不丢注释。

## 3. Wadler printer 的判定方式

对每个 `Group`，判断"压平后到本组内**下一个强制换行为止**是否放得下"。

- 放得下 → 组内软断点输出为空格
- 放不下 → 全部换行

**为什么按"到下一个硬换行"而不是整组宽度**：一段长语句里，短的小组（比如列清单里的一项）仍能保持单行，不会被整组拖累。

**视觉宽度**：CJK 字符算 2 列。中文注释和中文标识符不对齐会非常难看。

## 4. 布局规则（当前实现）

| 规则          | 行为                                                                                |
| ----------- | --------------------------------------------------------------------------------- |
| 语句之间        | 空一行                                                                               |
| 主子句         | `SELECT` / `FROM` / `WHERE` / `JOIN` / `GROUP` / `ORDER` / `SET` / `VALUES`… 各自起行 |
| JOIN 的 ON   | 缩进一级                                                                              |
| AND / OR    | 逐行，缩进一级                                                                           |
| 逗号          | 断点，由外层 Group 决定是否换行                                                               |
| 括号          | 内部作为独立 Group，放得下就 `(a, b, c)`                                                     |
| 函数调用        | `SUM(x)` / `COUNT(*)` 不加空格；`IN (…)` / `VALUES (…)` 加空格                            |
| CASE        | `WHEN` / `ELSE` 缩进一级，`END` 顶格                                                     |
| BEGIN / END | 块内缩进一级                                                                            |
| 注释          | 行尾注释贴前一个 token；单行块注释就地插入；多行块注释独立成行                                                |
| 点号          | `a.b.c` 不断行、不加空格                                                                  |
| GO          | 统一大写，保留 `GO 5` 的次数和行尾注释                                                           |

## 5. 踩过的坑

### 5.1 `GetTokenStream` 返回的是 `TSqlParserToken`，不是 `ISqlToken`

XML 文档里只列了 `antlr.IToken` 和 `TSqlParserToken`，实际能用的是后者（有 `TokenType` / `Line` / `Column` / `Text`）。

### 5.2 类型名被归为 `Identifier`

`int` / `varchar` / `datetime` 这些在 `TSqlTokenType` 里是 `Identifier`，不是关键字。需要按文本查表升级成 `Keyword`，否则不会大写。

### 5.3 复合运算符可能被拆开

`>=` / `<>` / `!=` 有时会被拆成两个 token，直接输出会变成 `> =`。分词阶段按文本合并。

### 5.4 括号处理容易多跳一个 token

配对右括号的循环里，`_i` 的推进必须由 `HandlePunctuation` 独占。第一版在调用方又 `_i++`，导致 `t(a,b,c)` 变成 `t(a, b, c)(1, 2, 3)`。**规则：谁负责推进 `_i`，必须唯一。**

### 5.5 `Indent` 节点管不到 `HardLine`

`HardLine` 相当于"换行 + 按当前 indent 补空格"。如果 `HardLine` 写在 `Indent` 的**外面**，那它换行时用的是外层缩进：

```csharp
// 错：HardLine 在 Indent 外，ON 换行时缩进还是 0
Concat(HardLine, Indent(doc))

// 对：把缩进直接写进文本
Text(new string(' ', indentSize) + "ON")
```

子句之间用 `HardLine` 分隔，所以 `ON` 的缩进最后是**在头部文本里直接补空格**解决的，没有用 `Indent` 节点。这类"层级靠 Indent、行间靠 HardLine"混用时容易踩，记在这里。

### 5.6 `Doc` 类名与命名空间冲突

`namespace SsmsSqlPlugin.Formatting.Doc` + `class Doc` 会互相遮蔽。改名为 `DocFactory`，用 `using static` 引入。

## 7. 三层结构：语句 → 子句 → 子句体

这是第二轮重构的核心。第一版只有一个大 Group，导致两个问题同时存在：

- 长 SELECT 列表**永远不折行**（列清单里没有硬换行点，Group 总判定"放得下"）
- 稍微长一点的语句就**整体展开**，短子句也被迫换行

按子句切开之后两个问题一起解决：

```
SELECT a, b, c FROM t          ← 列表短，整体压平
```

```
SELECT                         ← 列表长，只展开 SELECT 子句
    customer_id,
    customer_name,
    ...
FROM dbo.customer_orders       ← 其余子句保持单行
WHERE status = 'active'
```

**实现**：

- `TokenLayoutBuilder.SplitClauses()` 按主子句关键字切分，**括号内的不切**（子查询留给递归处理）
- 每个子句 = `Group(Concat(head, Indent(Line, bodyDoc)))`
- 头部与体之间用 **`Line`（压平=空格）而不是 `SoftLine`（压平=空串）** —— 用 SoftLine 会拼出 `SELECTa`，而且这是幂等失败的根源

## 8. 当前输出样例


## 10. 本轮补上的能力

| 能力                  | 效果                                                               |
| ------------------- | ---------------------------------------------------------------- |
| **SELECT 字段强制换行**   | 两列及以上一律每列一行（`SelectListStyle.Vertical`，默认值）。单列 / `SELECT *` 保持同行 |
| **子查询体展开**          | `FROM ( / IN ( / EXISTS ( / AS (` 后的括号按子句纵向展开，收括号回退对齐            |
| **标量子查询不展开**        | `SELECT (SELECT MAX(v) ...) AS mx` 保持单行，避免收括号后 `AS mx` 错位        |
| **控制流结构化**          | IF / WHILE / BEGIN...END / TRY...CATCH / ELSE IF 全部按 AST 子节点区间排  |
| **MERGE**           | MERGE INTO / USING / ON / WHEN...THEN 分支三段式，动作缩进                 |
| **存储过程 / 函数 / 触发器** | `AS` 之后 body 交给语句块排版                                             |
| **BETWEEN...AND**   | 不再把 BETWEEN 的 AND 当成逻辑连接词断行                                      |
| **注释**              | 行尾注释不再多出空行；行内块注释与逗号之间不留空格                                        |
| **运算符括号**           | `(a + b) * (c - d)` 乘号两侧正确留空格                                    |

## 11. 这一轮挖出的 5 个真 bug（都很隐蔽）

### 11.1 `ExplicitVisit(TSqlStatement)` 永远不会被调用

`TSqlFragmentVisitor` 按节点**具体类型**分发，抽象基类 `TSqlStatement` 上没有对应的  
ExplicitVisit 目标。写 `public override void ExplicitVisit(TSqlStatement node)`  
编译能过、跑起来**一条都收不到**（实测 count=0）。

后果：语句切分静默退化成"整批一条"。格式化照样有输出，只是所有语句边界丢失 ——  
`IF...BEGIN...END` 全糊成一行，几乎无法察觉是这里的问题。

**正解**：重写 `Visit(TSqlStatement node)`（后序遍历，需要自己保证"同起点外层在前"）。

### 11.2 AST token 索引与排版 token 索引错位

`FirstTokenIndex / LastTokenIndex` 是按 ScriptDom **原始 token 流（含空白）**&#x7F16;号的，  
而排版 token 列表丢掉了空白。少了映射，所有语句区间都指到错的位置，  
输出变成 `PRINT\nBEGIN` 这种关键字错位。

**正解**：`SqlTokenizer` 建 `RawToLayout` 映射数组（-1 = 被丢弃的空白），  
`StatementSplitter` 用它翻译区间。

### 11.3 `Identifier 在关键字表里就升级` 会改坏列名

`level / status / type / name / key / count / max` 这些词 ScriptDom 都报 Identifier，  
但它们**不是保留字**，当列名极常见。原来的"在 All 表里就升级"会输出  
`WHERE LEVEL = 'vip'`，把列名吃掉了大小写。

**正解**：只有**类型名**（`DataTypes` 表）允许无条件升级；  
上下文固定搭配词（MATCHED / TARGET / NOCOUNT / PARTITION / BY…）走  
`IsContextualKeyword` 按前导 token 判断。

### 11.4 `Measure` 遇硬换行没终止

`Fits()` 递归测量时，遇到 `HardLine` 只让当前调用返回 true，  
但 `ConcatNode` 的循环继续测后面的节点，把硬换行之后的文本也累加进去。于是

```
WHERE a = 1
    AND b = 2
    AND c = 3
```

被判成整行超宽 → `WHERE` 后白白换行。

**正解**：加 `done` 出参，一旦置位后续节点全部忽略。

### 11.5 `Indent` 节点管不到第一行文本

`Indent` 只影响**换行之后**的缩进。像 `BuildFlatRange` 这种产出纯 `Text` 的片段，  
外层套 `Indent` 完全没效果（MERGE 的 USING/ON、WHEN 分支动作都踩过）。

**正解**：需要缩进的多行文本用 `PrefixLines()` 逐行加前缀空格。

## 12. 剩余不足

| 项           | 说明                                              |
| ----------- | ----------------------------------------------- |
| 逗号位置        | trailing（逗号在行尾）。`commaPlacement` 配置未接           |
| 对齐          | 别名对齐、列定义对齐都没做                                   |
| 括号风格        | 只有 expanded / not expanded 两档，没做 hanging indent |
| 注释相对位置      | 行尾注释按"贴在当前行尾"处理，原行内容变了可能错位                      |
| `SELECT` 单列 | 目前 `SELECT a` 不换行，未提供"即使单列也换行"的开关               |

这些都属调优，不影响主链路可用。
