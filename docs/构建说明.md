# 构建说明

> 结论：**完全离线自足**，不依赖 NuGet、不依赖 VSSDK BuildTools 的 MSBuild 目标。
> 原因：本机 `api.nuget.org` 不通（curl 返回 000），任何 `PackageReference` 都会还原失败；
> 而且即使能通，NuGet 上的 SDK 版本也未必与 SSMS 自带的一致，反而不如直接引用宿主程序集。

## 三条命令

```bash
# 1. 编译（net48，引用宿主 PublicAssemblies 里的程序集）
dotnet build spike/MinimalVsix/SsmsSqlPlugin.Probe.csproj -c Release

# 2. 打包（生成 dist/*.vsix + dist/deploy/）
python spike/MinimalVsix/build.py

# 3. 部署（需要管理员，脚本自己提权）
spike\MinimalVsix\install.bat
```

## 关键约定

| 项 | 做法 | 原因 |
|---|---|---|
| 框架 | net48 | SSMS 22 跑在 .NET Framework 4.8，不能上 .NET 8 |
| SDK | 普通 `Microsoft.NET.Sdk`，不用 `Microsoft.VSSDK.BuildTools` | 后者是 NuGet 包，离线拉不到；我们手工写 pkgdef 代替它生成 |
| 引用 | 全部指向 `<SSMS 安装目录>\PublicAssemblies\*.dll`，且 `Private=false` | 宿主进程已有同名程序集；复制过去会造成类型标识冲突 / 绑定失败 |
| pkgdef | 手写，`$PackageFolder$` 由宿主在加载时替换成扩展目录 | 与 CreatePkgDef.exe 生成的等价，只是少了无关项 |
| .vsix | Python `zipfile` 打 OPC 包，含 `[Content_Types].xml` | 不依赖任何打包工具 |
| 版本对齐 | 覆盖 `SsmsIde` 属性即可切 SSMS 版本（未来 21/20 包） | `/p:SsmsIde=...` |

## 已踩到的坑

1. **ScriptDom 不在 `IDE\` 根目录**，而在 `IDE\Extensions\Application\`。
2. **SSMS 没有 `CommonExtensions\Microsoft\VSSDK`**（那是 VS 的老路径），VS 2026 的 VSSDK 在 `Common7\IDE\Extensions\VSSDK`。
3. **`UIContextGuids80` 不在 `Microsoft.VisualStudio.Shell.Interop.8.0.dll`**（虽然里面有这个字符串），实际类型在 `Microsoft.VisualStudio.Interop.dll`。少引这个会报 `CS0103`。
4. `InstalledProductRegistrationAttribute` 已过时（VS 提示改用 VSIX manifest），别再用。
5. 扩展目录 `Program Files` 下**不可写**，部署必须提权。
6. **`.bat` 必须是纯 ASCII 或 GBK 编码**。写成 UTF-8 中文后，cmd 按 GBK 解码，中文变乱码且乱码里混入的字节会把命令行拆断，表现是一堆「`0` 不是内部或外部命令」。所有 `.bat` 一律 ASCII + CRLF，用 Python 以 `encoding='ascii'` 落盘，别用编辑器默认保存。
7. **`.bat` 里不要用 PowerShell 自提权**（`Start-Process -Verb RunAs`）。这类构造会被安全策略拦，也可能被杀软标记。正确做法：脚本检测 `net session`，非管理员就打印提示、让用户右键「以管理员身份运行」。
8. **装完必须 touch 扩展配置标记，否则包静默不加载**。Shell 靠 `%LOCALAPPDATA%\Microsoft\SSMS\22.0_a832b12e\Extensions\extensions.configurationchanged` 的时间戳决定是否重建扩展缓存；VSIXInstaller 静默安装**不会**更新它，于是继续用旧缓存（指向已删除的旧目录 + 旧 AssemblyVersion）→ 包根本不加载，且日志一个字都没有。每次装完都要：
   ```bash
   touch "%LOCALAPPDATA%\Microsoft\SSMS\22.0_a832b12e\Extensions\extensions.configurationchanged"
   ```
   开发期更快的方式：直接覆盖用户级扩展目录里的文件 + touch，不必跑安装器。
9. **菜单不要走 CTC**。VSCT / `.ctmenu` / pkgdef `Menus` 段在 SSMS 22.11 + 手搓 VSIX 的组合下不生效，全部废弃。改用运行时注入（`IVsProfferCommands3.AddNamedCommand` + `CommandBars`），细节见 `SSMS扩展接入踩坑.md` §4.4。
10. **`pkgdef` 用 UTF-16 LE + BOM**，与微软自带的一致（UTF-8/ASCII 会让字符串值以单字节写进 `privateregistry.bin`，与 Shell 预期的 UTF-16 不符）。
